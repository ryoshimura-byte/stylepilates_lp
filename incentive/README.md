# 担当顧客インセンティブ集計ツール

Square API（サブスクリプション・請求書・顧客）から毎日データを取得し、社員ごとの
「担当顧客インセンティブ」（4ヶ月継続率・ポイント・半期の支給額）を集計して、
Googleスプレッドシート（または同じ構成のCSV）に書き出します。

- Python 3.11 以上。Square の取得・集計・CSV 出力は標準ライブラリだけで動きます
- Googleスプレッドシートに書き込む場合のみ `pip install -r requirements.txt`

## セットアップ

```bash
cd incentive
cp .env.example .env                 # SQUARE_ACCESS_TOKEN=... を記入（本番環境のトークン）
cp data/assignments.example.csv data/assignments.csv     # 担当表を用意
cp data/name_aliases.example.csv data/name_aliases.csv   # 表記ゆれ表（任意）
python -m incentive_tool run         # 1回実行 → output/ にCSVが出ます
```

アクセストークンはコードや config.toml には書かず、環境変数か `.env` に設定してください
（`.env`・担当表・出力・DB は `.gitignore` 済みで、git には入りません）。

### 担当表（data/assignments.csv）

| 担当社員 | 会員名 | 顧客ID（任意） |
|---|---|---|
| CHINA | 山田 花子 | |
| AMI | 篠原 見佳 | |

- 社員は `config.toml` の `[employees] names`（CHINA / TOMOKA / AMI / MIZUKI / RIHO）
- RIHO は `not_eligible` に入っているので、集計表には出ますが支給額の計算からは除外されます
- 名前の照合では、空白・全角/半角・カタカナ/ひらがな・敬称・姓名の順序の違い・一部の異体字（髙/高、﨑/崎）を吸収します
- 漢字の表記ゆれ（例：「篠原 みか」と「篠原 見佳」）は `data/name_aliases.csv` に1行書けば同一人物として扱います。
  同名の別人がいる場合などは、担当表の「顧客ID」列に Square の顧客ID を入れると最優先で照合されます
- 担当表にない名前が出ても止まらず、「更新ログ」に警告（似た名前の候補つき）を出して「未割当」として集計します

## 実行

| やりたいこと | コマンド |
|---|---|
| 日次実行（当月を上書き、前月までを確定） | `python -m incentive_tool run` |
| 過去の月を再集計（確定済みでも上書き） | `python -m incentive_tool run --month 2026-09` |
| 毎日自動実行（cron に登録） | `python -m incentive_tool install-cron` |
| cron の行を確認するだけ | `python -m incentive_tool install-cron --print-only` |
| cron が使えない環境で常駐 | `python -m incentive_tool serve` |
| Square のデータを保存（調査用） | `python -m incentive_tool fetch --dump dumps/today` |
| 保存したデータで集計（APIを呼ばない） | `python -m incentive_tool run --from-dump dumps/today` |
| テスト | `python -m unittest discover -s tests` |

- 実行時刻は `config.toml` の `[schedule] time`（日本時間）。変更したら `install-cron` をもう一度実行してください
  （`serve` の場合は次回から自動で反映）。`CRON_TZ` に対応していない cron の場合はサーバーのタイムゾーンを日本時間にしてください
- 当月分は毎回「途中経過」として上書きされます。月が変わって最初の実行で前月分が「確定」として固定され、以降は
  `--month` で再集計を指示したときだけ更新されます
- 月次記録は（月, 社員）単位で上書き保存するので、同じ日に何度実行しても重複しません
- 失敗した日も「更新ログ」に残ります。毎回 Square から全データを取り直して集計し、未確定のまま残っている過去月
  （`[tracking] start_month` 以降）もまとめて確定するので、翌日の実行で自動的に取り返せます
- Square API はページネーション（cursor）を最後まで辿り、リクエスト間隔を空け、429（レート制限）や 5xx は
  Retry-After／指数バックオフで再試行します

## 集計ロジック

対象月を M とします。

| 項目 | 定義 |
|---|---|
| 4ヶ月継続 | 決済が4回完了していること（請求日ではなく、invoice が支払い済み＝PAID の件数で判定） |
| 担当人数 | 契約が ACTIVE または PAUSED の担当会員数。当月は実行時点、確定月は月末時点の人数 |
| 判定対象人数 | 4回目の決済日が M に来る会員（`start_date` と `monthly_billing_anchor_date` から算出。6月入会→9月）＋ 保留から M に決着した会員 |
| 継続人数 | 判定対象のうち、4回目の決済が完了した会員 |
| 退会人数 | 4回目の決済の前に解約した会員（解約予約で、次の決済日より前に契約が終わる場合も含む） |
| 保留 | 決済エラー（カード期限切れ・残高不足）や休会（PAUSED）で4回目が完了していない会員。退会に数えず、決済が完了した月（または解約した月）に判定 |
| 退会率 | 退会人数 ÷ 判定対象人数 |
| 判定 | 退会率 25% 以下で「達成」、超えたら「未達」。当月は「途中経過」、月が終わってから「確定」 |
| ポイント | 達成かつ担当人数 20 人以上 → 担当人数 ÷ 10、それ以外 → 0（当月分は見込み） |

- プラン変更（例：ベーシック30%off → ベーシック）は、前の契約の終了から `plan_change_gap_days`（31日）以内に
  次の契約が始まっていれば同じ在籍として通算し、解約には数えません。決済回数も通算します
- それより空けて再開した会員（例：2ヶ月以上空けて再開）は休会していた人として、同じ在籍のまま決済回数を通算します。
  空白期間は休会中（担当人数に含め、退会には数えない）として扱います（`rejoin_as_pause = false` で新規入会扱いに変更可）
- 一度も決済されずに終了した契約（申込みの取り消し・重複登録など）は会員として数えません
- 当月の判定対象のうち、まだ決済日が来ていない会員は「未確定人数（当月）」に表示されます

### 半期集計（シート「設定・集計」）

- 4〜9月（上期）、10〜3月（下期）ごとに、社員別の確定ポイント合計と、当月を含めた見込みポイント合計
- 構成比 ＝ 各社員のポイント ÷ 支給対象社員のポイント合計（RIHO は表示のみで分母から除外し、配る総額を全額配分）
- 支給額 ＝ 配る総額 × 構成比（円未満切り捨て）。配る総額は `config.toml` の `[payout] total_amount`（初期値 300,000円）

## 出力

| シート / CSV | 内容 |
|---|---|
| 1. 月次記録 | 月, 担当社員, 担当人数, 判定対象人数, 継続人数, 退会人数, 退会率, 判定（確定／途中経過）, ポイント, 保留人数, 未確定人数, 更新日時 |
| 2. 設定・集計 | 合格ライン, 最低担当人数, 配る総額, 社員ごとの合計ポイント・構成比・支給額, 最終更新日時 |
| 3. 保留一覧 | 決済エラー・休会で判定を持ち越している会員（名前・対象月・理由・決済回数・最終エラー日） |
| 4. 更新ログ | 実行日時, 取得件数, 警告・エラー |

このほか、確認用に `output/会員別判定/YYYY-MM.csv`（会員ごとの判定結果）をローカルにだけ出力します。

### Googleスプレッドシートに書き込む場合

1. Google Cloud でサービスアカウントを作成し、鍵（JSON）をダウンロード
2. 書き込み先のスプレッドシートを、サービスアカウントのメールアドレスに「編集者」で共有
3. `.env` に `GOOGLE_SERVICE_ACCOUNT_FILE=/path/to/key.json`、`config.toml` の `[output]` に
   `mode = "sheets"`（CSVも残すなら `"both"`）と `spreadsheet_id` を設定
4. `pip install -r requirements.txt`

シートがなければ自動で作成し、毎回内容を書き換えます。設定値の変更は `config.toml` で行ってください
（シート上の設定欄は表示用です）。

## 注意・前提

- 決済完了日は、支払い済み invoice の最終更新日時（日本時間）を使っています
- 決済エラーは、期日を過ぎて UNPAID / FAILED / PARTIALLY_PAID のままの invoice で判定します（`config.toml` で変更可）
- 保留一覧には、4回目の予定月から `pending_lookback_months`（12ヶ月）以内の会員を表示します
- Square 以外（Airペイ・現金など）で支払っていた期間がある会員は、`data/member_overrides.csv`
  （列：会員名, 顧客ID, 実際の入会日, Square外の決済回数, 退会扱いしない, 備考）に書くと、その回数を決済回数に足して判定します。
  Square 上は解約になっていても登録し直す予定の会員は「退会扱いしない」に 1 を入れると、退会ではなく未確定・保留として扱います
  （例：`data/member_overrides.example.csv`）
- テスト用の顧客などは `[tracking] exclude_customer_ids` に顧客IDを入れると集計から外せます
